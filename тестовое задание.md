## что нужно сделать?

### 1. модель склада

для модели вам понадобится реализовать в симуляторе физические стены, узлы и рёбра. узлы - точки навигации робота на которые робот и должен ездить. рёбра - дорожки между узлами, по факту разрешеная траектория передвижения робота, чтобы добраться из узла A в узел B.
сам склад пусть будет такой:

```
_____________________________
|                            |
| O - O - O - O - O          |
| |   |   |   |   |          |
| O   O   O   O   O   O - P  |
| |   |   |   |   |   |      |
| O - O - O - O - O - O - P  |
| |   |   |   |   |   |      |
| O   O   O   O   O   O - P  |
| |   |   |   |   |          |
| O - O - O - O - O          |
|____________________________|
```

хардкорный склад для стресс-теста оркестратора:
```
_____________________________
|                            |
|                     O - P  |
|                     |      |
| O - O - O - O - O   O - P  |
| |       |       |   |      |
| O - O - O - O - O - O - P  |
|                     |      |
|                     O - P  |
|                     |      |
|                     O - P  |
|____________________________|
```

спавн робота-одиночки на любой из точек парковки (`P`)

### 2. симулятор робота

по имеющейся карте должен кто-то передвигаться, поэтому вам потребуется реализовать симуляционного робота, который способен:

- передавать информацию о позиции, скорости, текущем приказе;
- получать и обрабатывать приказы (перемещение, остановка, ручное управление);
- репортить об ошибках (застрял в препятствии, не найдена точка, робот слишком далеко от ближайшей точки/ребра)
- двигаться взад и вперёд, поворачиваться

минимальная модель робота: сплюснутая коробка с двумя рабочими колёсами

### 3. оркестратор приказов

очень кстати пригодится изучить VDA5050: вам предстоит запустить нескольких симуляционных роботов в одной среде, а для их управления потребуется реализовать минимальный оркестратор\диспетчер.

роботы обязаны отчитываться управляющей системе и получать от системы приказы на перемещение или парковку.

система при выдаче приказов должна учитывать занятость узлов и путей, чтобы роботы друг друга не сбили и не ехали по одному и тому же маршруту, когда есть свободные пути
реализовать сценарий "Тёмный цех": когда включено, система постоянно будет накидывать роботам приказы на перемещение по рандомным дальним точкам, чтобы роботы были постоянно в движении

## критерии готовности

- роботы корректно ездят по любым точкам, поворачиваются в сторону следующего узла
- позиции роботов всегда актуальны и в интерфейсе за ними можно свободно следить
- роботы никогда не блокируют друг другу передвижение, в узких коридорах друг другу уступают
- оркестровщик блокирует графы на которых стоит застрявший робот, которого ждать бесполезно
- оркестровщик стабилен даже при плохой связи с роботом (проверить троттлинг и потерю связи)
